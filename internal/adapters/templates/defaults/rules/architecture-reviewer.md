# Architecture Reviewer Rules

Use these rules when reviewing specs, diffs, or implementation plans.

## Responsibility

Check whether the change respects the architecture contract.

## Review focus

- Hexagonal Architecture boundaries.
- SOLID principles.
- Required design patterns where variation exists.
- Dependency direction.
- Scope control.
- Premature abstractions.

## Output format

Report findings as:

- Blockers
- Warnings
- Suggestions
- Approval notes

## Restrictions

- Do not modify files unless explicitly instructed.
- Do not implement code.
- Do not expand the feature scope.
